# S3 Service

The platform exposes a single S3-compatible endpoint per region. Users connect with platform-issued credentials. The backend provider is never visible to them.

## Gateway

- A stateless S3 gateway runs mirrored across ingress nodes — multiple identical replicas, no coordination between them.
- Accepts standard S3 API calls (AWS SDK, rclone, s3cmd, etc.).
- Validates platform credentials, resolves organization identity, enforces quotas, then proxies or redirects to the backend.
- Because it is stateless, replicas can be added or replaced freely. Ingress nodes are the placement target.
- Built on [`s3s`](https://github.com/Nugine/s3s): handles inbound request parsing, SigV4 validation, and operation routing. The `s3s-aws` companion crate bridges to `aws-sdk-s3` types for forwarding. The gateway implements the `s3s::S3` trait — virtual operations are handled directly from DB state, forwarded operations are translated and sent to the provider via `aws-sdk-s3::Client`.

## Credential Model

- Users receive platform-issued credentials: `access_key_id`, `secret_access_key`, `endpoint_url`.
- Users never receive or see backend provider credentials.
- At request time: platform credentials validated → organization resolved → backend credentials looked up → signed request forwarded to provider.

## Bucket Model

- Each platform logical bucket maps 1:1 to a real provider bucket.
- No key prefix translation. Object keys are stored and retrieved as-is.
- Every bucket record holds: `organization_id`, `name`, `provider_bucket_name`, `provider_credentials_id`, `created_at`.
- `provider_credentials_id` points to a credential set — either the platform's regional account or an org-owned provider account.
- `ListBuckets` is answered from DB, never from the provider. All other operations look up `provider_bucket_name` + credentials from DB and forward directly.

### Provider bucket limits

| Provider | Default | Maximum |
|---|---|---|
| Cloudflare R2 | 1,000,000 | 1,000,000 |
| AWS S3 | 10,000 | 1,000,000 (on request) |
| Ceph / MinIO | Unlimited | Unlimited |

At any scale where AWS's 10k default becomes a constraint, an operator is large enough to raise it via a support request.

## Provider Credentials

The gateway supports two credential sources per bucket:

- **Platform-managed**: the platform's regional provider account. Default for all buckets. Billing goes through the platform. Bucket name is derived as `{org_id}-{bucket_name}`.
- **Org-owned (Future)**: the org supplies their own S3 credentials (`endpoint_url`, `access_key_id`, `secret_access_key`). Stored encrypted at the org level. Billing goes directly to the org's provider account.

Org-owned credentials are stored in an `org_provider_accounts` table (name, provider type, endpoint, credentials). An org can have multiple provider accounts configured and choose which one to use per bucket.

When creating a bucket, an org can select any of their configured provider accounts. If none is selected, the platform regional account is used.

Credential health is checked on a heartbeat. If stored credentials stop working, affected buckets are flagged and the gateway returns a clear error to the user.

For org-owned buckets, the heartbeat also verifies the provider bucket still exists (`HeadBucket`). If the bucket has been deleted outside the platform, the bucket is flagged as unavailable and traffic is rejected until the org resolves it. The platform does not attempt to recreate it.

## Request Modes

- **Proxy (default)**: gateway forwards the full request to the provider and returns the response. Full audit trail, quota enforcement.
- **Presigned redirect (scale)**: gateway validates platform credentials and issues a short-lived provider-presigned URL. Client hits the provider directly. No bandwidth cost to the platform for large transfers.

## Endpoints

- **External**: `s3.<region>.platform.dev` — exposed via Cilium Gateway (HTTP listener with TLS).
- **Internal**: `s3.internal` — workloads inside the cluster use this. Traffic stays inside the Cilium mesh and never leaves the cluster.
